Para iniciar um novo projeto, conduzo uma entrevista de definições com as seguintes perguntas (nesta ordem):

  1. Nome do projeto — nome descritivo
  2. Abreviação — usada para nomear schemas no Unity Catalog (ex: vda para "Vendas")
  3. Objetivo — uma frase que descreve o que o projeto entrega
  4. Pergunta que o projeto responde — a questão de negócio central
  5. Fontes — para cada fonte: nome, origem (tabela UC, arquivo, API, etc.) e periodicidade (batch diário, streaming, etc.)
  6. Escopo — o que está incluído e o que explicitamente não está
  7. Consumidores — quem (pessoa, equipe ou sistema) vai consumir o resultado

Depois disso, há uma segunda entrevista sobre o pipeline: quais etapas o projeto terá, o que cada uma consome e produz, e onde as linhagens convergem.

Com essas respostas eu crio a estrutura de pastas, os quatro documentos de governança (definicoes_projeto.md, mapa_pipeline.md, decisoes_arquiteturais.md, evolucao_projeto.md) e os schemas no Unity Catalog.
