Revisei o notebook de ingestão de interrupções do projeto de continuidade de fornecimento. Identifiquei 16 problemas críticos que impedem produção, organizados por gravidade:

🔴 FRENTE 1 — CORREÇÃO (5 problemas críticos)

1.1 Lista hardcoded de anos não verifica arquivos reais

Célula 5, linhas 2-3

# ERRADO — anos hardcoded, não verifica se arquivos existemanos_disponiveis = [2020, 2021, 2022, 2023, 2024]

Impacto: O loop tentará processar anos que podem não ter arquivo disponível, gerando falhas em runtime.

Correção:

# Listar arquivos realmente disponíveis via API ou scraping do portal ANEEL# Exemplo: requests.get(url_catalogo) e parsear JSON/HTML com lista de anos

1.2 URL base é placeholder não funcional

Célula 3, linha 8

URL_BASE_ANEEL = "https://dadosabertos.aneel.gov.br/dataset"

Impacto: URL incompleta impedirá download dos arquivos.

Correção: Substituir por URL completa testada (ex: https://dadosabertos.aneel.gov.br/dataset/interrupcoes-de-energia/{ano}/resource/{resource_id})

1.3 Comparação de last_modified como string não é confiável

Célula 6, linha 26

# ERRADO — compara strings de data sem parsingWHERE last_modified = '{last_modified}'

Impacto: Formato de data HTTP pode variar, causando falsos negativos (reprocessamento desnecessário) ou falsos positivos (skip indevido).

Correção:

from email.utils import parsedate_to_datetimelast_modified_dt = parsedate_to_datetime(last_modified)# Gravar e comparar como TIMESTAMP

1.4 Quebra de lazy evaluation — count() antes de write()

Célula 6, linha 38

# ERRADO — força computação completa 2xnum_registros = df_raw.count()  # 1ª computaçãodf_bronze.write.mode("append").saveAsTable(...)  # 2ª computação (recomputa DAG do zero)

Impacto: Dobra o custo de processamento. Para 1M de linhas, processa 2M.

Correção:

df_bronze = df_bronze.cache()  # Cacheia antes do countnum_registros = df_bronze.count()df_bronze.write.mode("append").saveAsTable(...)df_bronze.unpersist()

1.5 Exceção genérica captura erros diferentes como iguais

Célula 6, linha 66

# ERRADO — timeout de rede, 404 e parsing error viram "erro ao processar ano"except Exception as e:

Impacto: Impossível diagnosticar causa raiz. Um 404 (arquivo não existe) é esperado, timeout de rede não é.

Correção:

except requests.exceptions.HTTPError as e:    if e.response.status_code == 404:        logger.info(f"Arquivo não disponível para {ano}")        continue    raiseexcept requests.exceptions.Timeout:    logger.error(f"Timeout ao acessar {url_arquivo}")    raise

🟠 FRENTE 2 — PREMISSAS OCULTAS (7 problemas críticos)

2.1 Status SUCCESS gravado sem validar volume processado

# Antes de gravarcount_entrada = df_raw.count()count_saida = df_bronze.count()assert count_entrada == count_saida, f"Perda detectada: {count_entrada} → {count_saida}"
